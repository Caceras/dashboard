Every project in `/projects` has five fields that decide whether it ships on time: `status`, `priority`, `progress`, `deadline`, `budget`. Keep these honest and Works will catch problems before clients do.

## The four phases

### 1. Plan (status: `planned`)

Write the project description like a pull-request title — one sentence, action-oriented. Set `priority` based on **client retention risk**, not perceived urgency. A high-priority project is one where slipping breaks trust permanently.

### 2. Build (status: `in_progress`)

`progress` updates only when something concrete shipped — a draft, a deploy, a sign-off. "I worked on it today" is not progress. The percentage is your honest read of how much value the client could already extract if you stopped now.

### 3. Review (status: `review`)

Move to `review` when the deliverable is in the client's hands. Set a 5-business-day timer. If they go silent past day 5, the [contract approval clause](/docs/clients/contracts) kicks in.

### 4. Done or blocked (status: `done` / `blocked`)

`done` means **invoiced and paid**, not "I sent the file". `blocked` means waiting on a specific external event with a specific name and date in the description. "Waiting on feedback" is not blocked. "Waiting on assets from Sarah, expected Nov 12" is blocked.

## Priority, decoded

| Priority | When to use |
| --- | --- |
| `high` | Slipping this damages the client relationship permanently. |
| `medium` | Slipping this disappoints but doesn't end the engagement. |
| `low` | This is a nice-to-have. Genuinely. |

If everything is high, nothing is. Force-rank.

## Deadline hygiene

The deadline on `/projects` is what you tell the client. The deadline in your head is two weeks earlier. The Today page warns when `deadline - today &lt; 7 days AND progress &lt; 60%`. When that warning fires, you have one of three honest moves:

1. **Cut scope** with the client's blessing.
2. **Push the deadline** with the client's blessing.
3. **Cancel a meeting** to make room.

Any other move is a lie to yourself.

## Budget reality check

Every Friday, the weekly ritual asks: hours logged × hourly_rate vs. budget. If you're past 70% of budget at 50% of progress, that's a conversation to have **with the client**, not internally. They'd rather know now than be surprised at delivery.

::callout{icon="i-lucide-alarm-clock"}
**Rule of thumb:** A project at 100% budget and &lt; 100% progress should never reach status `done` without a budget extension or scope cut on file.
::

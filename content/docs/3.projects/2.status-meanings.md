The pipeline ribbon on Today is only as useful as the precision of these definitions. Memorize them. Enforce them.

## planned

The project exists in Works because a contract is signed and a kickoff is scheduled. **Not** because someone mentioned it in a call. `progress` is `0`. `started_at` is `null`. If `started_at` is set, the project is no longer planned.

## in_progress

`started_at` is set. You've spent time on this. `progress` is between `1` and `99`. The deliverable is not in the client's hands yet.

## review

The deliverable is in the client's hands. You are waiting for **their** action: feedback, sign-off, asset upload. The 5-day approval clock is running. `progress` is typically `≥ 90`.

## blocked

Waiting on a specific external event with a name, an owner, and an expected date. Examples:

- ✅ "Waiting on logo files from Sarah, ETA Nov 12"
- ❌ "Waiting on client" (vague — almost always actually `review`)
- ❌ "Need to think about it" (you are not blocked, you are procrastinating)

Anything in `blocked` for &gt; 48 hours surfaces in **Needs attention** on Today.

## done

**Three things are simultaneously true**:

1. The deliverable was accepted.
2. The final invoice was sent.
3. The final invoice was paid.

Until all three are true, a project is not done. `finished_at` is set when it is.

## A note on `done` vs. `archived`

There is no `archived` status for projects (only for clients). A `done` project lives in history forever — that's what makes the project list a real ledger of work.

::callout{icon="i-lucide-info"}
**Anti-pattern:** Marking a project `done` when the invoice is sent but unpaid. The pipeline ribbon will lie. The Friday reconciliation will catch you. Don't.
::
